## 3. How to Grant Admin Access

### Method 1: Through the App (Recommended)

1. The new user signs in with Google on the app (`learn.tatvamniramaya.com`)
2. Their profile is automatically created in Firestore under `/users/{uid}`
3. Go to **Firebase Console → Firestore Database → Data**
4. Navigate to `/users` collection
5. Find the new user's document (match by email or name)
6. Click **"Add field"** or edit existing `role` field
7. Set `role` to `"admin"` (string)
8. Click **Save**

### Method 2: Directly from Firebase Console

1. Go to **Firebase Console → Firestore Database → Data**
2. Click **"Start collection"** (if `users` doesn't exist)
3. Collection ID: `users`
4. Document ID: Use the user's Firebase Auth UID
   - Find this in **Authentication → Users** tab
5. Add fields:
   ```
   uid        : string  → "auth-uid-here"
   name       : string  → "Person Name"
   email      : string  → "email@example.com"
   role       : string  → "admin"
   createdAt  : timestamp → now
   updatedAt  : timestamp → now
   ```

### Verify Admin Access

After setting `role: "admin"`, the user should:
- Be able to access `/admin` routes
- See all data in admin tables
- Have write access to workshops, services, courses, etc.

> **Security Note:** Admin checks happen in Firestore Security Rules (`firestore.rules`). The rules verify `request.auth.uid` exists in `/users/{uid}` with `role == "admin"`.

## 4. Firestore Security Rules

The rules file lives in the repo at `firestore.rules`. **Always keep this in sync with the Firebase Console.**

### Deploy Rules from Console

1. Go to **Firebase Console → Firestore Database → Rules**
2. Copy the contents of `firestore.rules` from the repo
3. Paste into the rules editor
4. Click **Publish**

### Rule Summary

| Collection | Public Read | Public Write | Admin Write | User Own Data |
|-----------|-------------|--------------|-------------|---------------|
| `users` | ❌ | ❌ | ✅ | ✅ (own doc) |

## 5. Common Operations

### 5.1 Manually Add a Workshop

1. Go to **Firestore Database → Data**
2. Click **"Start collection"** → name it `workshops` (if it doesn't exist)
3. Click **"Add document"** → let Firestore auto-generate ID
4. Add fields matching the Workshops schema above
5. Click **Save**

### 5.2 Hide a Service from Public View

1. Find the service in `/services` collection
2. Change `isVisible` from `true` to `false`
3. Save — the service disappears from the public app but stays in the database

### 5.3 Cancel a Booking

1. Find the booking in `/bookings` collection
2. Change `status` from `"upcoming"` to `"cancelled"`
3. Save — the booking status updates in the admin panel

### 5.4 Add a Testimonial

1. Go to `/testimonials` collection
2. Add document with `isApproved: false` for pending review
3. Change to `isApproved: true` and `isFeatured: true` to show on homepage

### 5.5 View All Payments

1. Go to `/payments` collection
2. Use filters or sort by `createdAt` descending
3. Check `status` field: `captured` = successful payment

## 6. Adding Composite Indexes

Some queries require **composite indexes**. If you see a console error like:

> *"The query requires an index. You can create it here: [...]"*

**To create an index:**

1. Click the link in the error message (it takes you directly to the index creation page)
2. Or go to **Firestore Database → Indexes**
3. Click **"Add index"**
4. Select the collection
5. Add the fields (e.g., `userId` Ascending + `createdAt` Descending)
6. Select **Query scope:** Collection
7. Click **Create**
8. Wait for status to change from "Building" to "Enabled" (usually 1–2 minutes)

### Required Indexes for This App

| Collection | Field 1 | Field 2 | Scope |
|-----------|---------|---------|-------|
| `payments` | `userId` (Asc) | `createdAt` (Desc) | Collection |
| `bookings` | `userId` (Asc) | `createdAt` (Desc) | Collection |
| `bookings` | `status` (Asc) | `createdAt` (Desc) | Collection |
| `testimonials` | `isApproved` (Asc) | `isFeatured` (Asc) | Collection |

## 9. Troubleshooting

### "Missing or insufficient permissions" Error

**Cause:** Security rules are blocking the read/write.  
**Fix:**
- Check if user is signed in
- Check if user's `/users/{uid}` document has `role: "admin"`
- Verify rules are published in Firebase Console

### Data Not Showing in App

**Cause 1:** Firestore is empty — run seed or add data manually.  
**Cause 2:** Query needs an index — check browser console for Firebase index creation link.  
**Cause 3:** Network issue — Firestore has offline persistence, but first load needs internet.

### Admin Pages Show Empty Tables

**Cause:** Collections don't exist yet or have no documents.  
**Fix:**
- Check Firestore Console → Data to verify collections exist
- If empty, add data manually or restore from backup

## 11. Razorpay + Firestore Flow

When a user makes a payment:

1. **Frontend** calls Razorpay Checkout
2. **Razorpay** returns `payment_id`, `order_id`, `signature`
3. **Frontend** calls `createPayment()` → writes to `/payments` collection
4. **Frontend** verifies signature (server-side ideally, client-side for now)
5. **Frontend** updates payment status to `"captured"`
6. **Admin panel** shows the payment in `/admin/payments`
